# MinClash 0.2.2

MinClash 是 Android Root TUN 工具，APK 内置完整的 KernelSU / Magisk 模块和 Mihomo v1.19.33-minclash.1 Android ARM64 内核。分发 `dist/MinClash.apk` 时一并提供 `dist/mihomo-v1.19.33-minclash.1-source.tar.gz` 对应源码包；安装模块所需文件已经包含在 APK 内。适用于 ARM64、Android 9 及以上，且内核支持 `/dev/tun` 或 `/dev/net/tun` 的 Root 手机。

## 安装和使用

1. 安装 `dist/MinClash.apk`，在 KernelSU / Magisk 中为 MinClash 授予 Root 权限。
2. 在 App「设置 → 内置模块」点击「安装内置模块」，安装成功后重启手机。无需另外下载模块 ZIP。如果管理器不支持直接安装，可点击「导出模块安装包」，再到管理器中从本地安装。
3. 在「配置 → 管理订阅」添加 Clash / Mihomo 订阅链接并启用，或导入本地 YAML，再回到「概览」点击「启动 TUN」。也可以先导入 `direct-smoke.yaml` 验证直连转发。
   「概览」通过 Mihomo 测试当前主代理节点到 Google 和 Cloudflare 的延迟，百度使用 DIRECT 出口作为直连参考。完成后约 5 秒再测，两个境外探测均失败时等待 15 秒。点卡片可手动重测。
4. 运行后可在「代理控制」切换规则、全局、直连模式，并在「代理组与节点」选择节点。全局模式使用 `GLOBAL` 组，规则模式使用配置中各条规则指定的组。
   代理组使用卡片显示组名及当前出口链路，支持搜索。节点页高亮当前选择，可搜索节点或代理组。点击列表项右侧「测速」可单独测试 Google 204 延迟；点击「测本组」可测试本组全部可测出口，不受搜索或隐藏失败筛选影响，最多同时测试 3 个。测试中可随时停止，关闭列表或旋转屏幕会取消剩余测试，已完成的延迟在本次列表中保留。测速只测延迟，不自动切换节点，也不代表下载速度。
   节点列表支持「延迟排序」和「隐藏失败」，未测试的出口仍会显示。点击 ☆ 收藏，收藏项置顶；启用延迟排序时，收藏与其他出口分别按延迟排列。收藏按订阅独立保存，本地配置共用一组收藏，订阅更新后同名节点沿用收藏。排序和隐藏偏好会记住，直连及拒绝等内置出口不参与批量测速或收藏。
5. 在「配置 → 管理应用分流」搜索已安装的应用，选择「跟随订阅规则」「直连」或指定代理组。例如，将 Claude 指向 `US` 组后，即使机场规则将 Claude 分到 `OpenAI`，也会优先走 `US` 组当前选择的节点。应用分流只在规则模式生效；运行中保存会短暂重连。
   列表可按应用、已指定、系统、Google 或自定义分类筛选。自定义分类支持搜索应用并编辑成员，应用分流仍按包名保存。
   列表先显示应用名称和包名，真实图标在后台按需加载并缓存；图标不可读时显示提示和检查入口，明确区分权限拒绝与其他读取失败。右上角「权限」显示查询权限、动态授权支持情况和已尝试读取的图标状态；尚未显示的应用图标不会误报为失败。设备支持且尚未授予的动态权限可在此申请；必要时可选择 Root 补充图标。
   进入配置页会后台预读应用分流。60 秒内可直接打开缓存列表，保存时读取最新配置并合并本次修改。权限变化、订阅更新或重新读取会更新缓存。
   点应用后选择「当前连接」，可刷新查看 Mihomo 能识别的活动连接、命中规则和出口路径。此视图在本地显示，不保存历史。如果当前配置没有开启完整的进程识别，可在窗口内临时开启，直到本次 Mihomo 运行结束。

「管理订阅」可保存多个订阅，重命名或删除未使用的订阅，并标记当前订阅。手动更新或切换前会下载配置，预览 YAML 中的节点增删、失效的应用分流和预计无法沿用的节点选择。动态代理提供者的节点以加载后的实际列表为准。确认后应用刚才预览的配置。TUN 运行时会短暂重连，若新配置无法启动 TUN 或恢复控制接口，App 会尝试恢复原配置和连接。导入本地 YAML 前请先停止 TUN。

「配置 → 自定义域名／IP 分流」支持精确域名（DOMAIN）、域名及子域名（DOMAIN-SUFFIX）、IPv4 和 IPv6 地址／网段（IP-CIDR／IP-CIDR6），出口可选直连、拒绝或配置中的代理组。可编辑、上移、下移和删除，最多 2000 条。域名只填主机名，不填协议、路径或通配符；支持国际化域名。单个 IP 可省略前缀，保存时规范为 /32 或 /128，网段会清除主机位。IP 规则带 no-resolve，不为匹配额外发起域名解析；已解析的目标仍可匹配。优先级为「应用分流 → 自定义规则（按列表顺序）→ 订阅规则」，仅规则模式下生效。更新或导入订阅、编辑应用分流后均保留这些规则；订阅缺少规则指定的出口时拒绝应用并在预览中提示，保存失败沿用原有回滚处理。

「配置」当前订阅摘要和订阅列表显示最近读取的用量与到期日期。「管理订阅 → 选择订阅 → 流量与有效期」可查看上传、下载、已用、剩余、到期时间及最近读取时间，并单独「刷新用量」，不会切换订阅或应用下载的配置。数据来自订阅服务器最终 HTTP 响应的 Subscription-Userinfo（upload/download/total 为字节，expire 为 Unix 秒），手动下载与自动更新时也会读取。缺失、异常、重复或溢出字段显示未提供，不冒充 0；expire=0 不显示为 1970 年。不是实时流量统计，失败时保留最近成功快照，不推测无限流量或永不过期。用量属于本机缓存，不进入备份。

「概览 → 连接管理」为独立页面，显示当前经过 Mihomo 的连接，可搜索全部内容或按应用／包名、目标域名／IP、出口路径筛选。详情包含命中规则、出口链、协议、连接上传下载和建立时间，可确认后断开指定连接；连接自行结束时按已结束处理，应用可能重新连接。页面可见期间约每 4 秒刷新，离开后停止轮询；不保存连接历史。一次最多处理前 5000 条，筛选后展示前 300 条并标明数量。应用归属依赖内核提供的进程或唯一 UID，无法识别时明确显示未知，不把共享 UID 猜成某个应用。可在页面内临时开启进程识别，只持续到本次内核运行结束。

0.1.9 将连接页改为统计、筛选和连接卡片，支持暂停／恢复自动刷新；打开详情时暂停自动轮询，刷新后尽量保留当前连接的滚动位置。横屏或键盘压缩可用空间时收起统计区，优先留出列表。读取失败不再清空已有结果，会标明上次更新时间且暂不可断开旧快照中的连接；明确显示未连接、暂无活动连接和筛选无结果。重复刷新会合并，断开或临时识别操作前的旧查询不会覆盖操作后的新状态。

自定义规则列表支持搜索域名、网段、类型或出口，卡片保留原列表序号，搜索后仍对原规则编辑或移动。规则表单根据域名、IPv4、IPv6 显示不同输入示例。订阅列表和用量详情使用卡片展示；已用与总额均有效时显示进度，缺失数据仍标注未提供，过期日期单独提示。已安装且无功能更新时，模块的「重新安装」不再作为主要操作强调。

单独刷新用量只读取服务器最终成功响应的头部，不解析或应用正文，也不要求正文为 YAML。配置下载兼容 gzip 及 UTF-8 BOM，传输声明大小和解压后的内容均受 2 MiB 限制；循环或缺失地址的重定向给出明确提示。用量缓存属于辅助信息，写入失败不会阻止订阅配置更新。控制接口兼容省略原因短语的 HTTP/1.0／1.1 状态行，并检查声明的响应长度，错误提示不包含服务器原始响应。连接 UID 和流量严格检查整数范围，避免溢出后误认来源，支持数字字符串和 processPath 字段。

如果订阅链接只能通过代理访问，请先连接可用代理再下载，也可以用其他方式下载 YAML 后从本地导入。遇到域名解析失败、连接错误或超时时，下载提示可直接打开诊断。

「设置」首页按「常用、连接、管理」分组，入口显示当前状态，点击后查看详细开关与说明。开机自启与热点共享位于「连接与启动」，开机自启默认开启，并在有有效配置时生效。「停止 TUN」停止当前会话；若要让下次开机也保持停止，请同时关掉自启开关。环境检测、内核日志、诊断报告与 DNS 修复统一位于「关于 → 诊断工具」。设置详情支持返回目录，旋转时保留页面与滚动位置。

「设置 → 备份与恢复」可将当前 YAML 源配置、全部订阅、应用分流、自定义分类、节点收藏及节点排序／隐藏失败／订阅自动更新偏好导出为 `.mcbak` 文件。需先有有效配置才能导出。通过系统文件选择器保存或打开，无需额外存储权限。默认使用密码加密，需输入两次至少 8 个字符的密码；也可明确关闭加密。未加密文件直接包含订阅链接和节点凭据，请妥善保管；密码不保存，遗忘后无法解密。

恢复前先校验文件并展示版本、时间和内容数量，不显示订阅链接或节点凭据。恢复会替换备份范围内的数据，不做合并；先安装并启用模块，再停止 TUN，可直接使用预览窗口内的「停止 TUN」。确认时重新检查本机配置和偏好，若预览后有变化则要求重新预览。配置经过原有 Mihomo 导入校验，恢复过程中写入或校验失败时尝试还原原配置与设置，回滚不完整会明确提示。恢复后 TUN 保持停止，由用户启动；已开启的每日订阅更新按恢复后的偏好重新安排。未安装应用的分流及分类仍按包名保留。

0.1.8 的备份新增自定义域名／IP 分流，并在预览中展示数量；可读取 0.1.7 的旧备份，旧备份不含自定义分流，恢复时该项为空。新备份的数据版本为 2，旧 App 会拒绝读取，避免静默丢弃新增规则。备份只迁移上述数据，不迁移 Root／Android 授权、通知开关、桌面图标、开机／热点设置、运行模式、当前选点、日志、订阅用量或第三方代理提供者缓存，均保留本机状态。文件最大 16 MiB；加密使用随机盐与随机 nonce、PBKDF2-HMAC-SHA256（210,000 次）和 AES-256-GCM，并认证文件头；未加密文件带 SHA-256 损坏校验。备份准备、解密和文件读写在后台运行，配置快照及恢复与订阅操作串行执行；旋转屏幕后任务与预览保留，密码输入不保存，App 整个进程被终止后需重新操作。

「关于 → 检查更新」会查询 GitHub Release，可在 App 内下载新版 APK，再由 Android 确认安装。覆盖安装需要使用相同 APK 签名。

下载 App 更新或订阅期间仍可启停 TUN、切换模式和节点。旋转屏幕等配置变化后，更新检查、下载与订阅预览任务继续执行，预览和错误提示保留至确认或关闭；Android 结束整个 App 进程后需重新操作。预览确认时仍会检查配置是否已变化。

「配置 → 自动更新当前订阅」默认关闭。开启后由 Android 在有网络时安排每日刷新，只更新当前订阅，保留应用分流。内容一致时继续使用当前连接。

自动订阅下载期间若配置或当前订阅变化，本次自动应用会跳过，最近更新记录会显示原因。

「关于 → 诊断工具」可分别检查 IPv4/IPv6 TUN 路由、主代理出口和手机 HTTPS 路径。分享前可预览记录，导出的文本仅包含必要版本、探测结果和固定故障码。配置中某组 DNS 上游全部指向本机时，重新导入、更新订阅或点击「修复本机 DNS 配置」可将该组替换为直连的公共加密 DNS（阿里云和 Cloudflare）。

在「设置 → 通知栏控制」开启控制通知并允许通知后，TUN 运行期间可查看上传与下载速率。0.2.2 默认使用常规优先级、无声音与振动的常驻通知，减少被归到低优先级区域的情况；网速更新沿用会话开始时间，不反复刷新时间抢位。系统中手动调整过的旧通知设置会保留，Android 9 上也保留已有渠道，可通过此页的「系统通知设置」调整；最终排序由系统决定。退出界面或划掉最近任务后，通知服务继续运行；被系统回收后请求自动重建，手机启动和覆盖安装后自动恢复已开启的通知栏控制，无需先打开 App。系统设置中的「强行停止」以及部分厂商的后台限制仍可能阻止恢复，可在系统应用设置中允许后台运行。通过「允许悬浮窗」为 MinClash 授权「显示在其他应用上层」后，点按模式或节点名会在当前应用上方打开对应的选择窗。给 MinClash 授予「使用情况访问」后，通知也会显示前台应用名称。

若小米／Redmi 手机划掉后台后通知一直消失，在「设置 → 通知栏控制 → 后台运行设置」打开系统自启动管理，允许 MinClash 自启动，并检查应用信息中的省电策略。真机发现未允许自启动时，系统会把划掉任务处理为强行停止整个应用；仅使用独立进程无法避免。允许自启动后通知可在系统清理后恢复，期间可能短暂消失。覆盖升级后若系统重置了自启动选项，需重新允许。

「设置 → 连接与启动 → 个人热点共享代理」让热点设备沿用当前代理模式、订阅规则和节点，无需在客户端手动设置代理。模块 0.0.8（修订号 7）及以上包含热点 DNS 修复、能力预检和持续恢复。安装后重启手机。开启共享开关后，启动 TUN，再开启系统个人热点；若提示系统网络共享加速仍在运行，需重启手机，让系统加载新的加速设置。共享状态会区分规则就绪、等待客户端流量、已有请求及已检测到回包；这些计数不代替客户端实际联网测试。应用分流按手机包名匹配，只适用于手机本机。关闭共享开关后，热点恢复系统网络共享。

下拉 Android 快捷设置，在编辑磁贴界面添加「MinClash TUN」。磁贴可启停 TUN，并显示运行、启动或重试状态。

「设置 → 外观 → 桌面图标」默认使用石墨灰，也可选择纯黑或深墨绿。切换后回到手机桌面查看。

## 运行方式

- App 通过 `su` 调用固定的控制命令，配置经标准输入交给模块。模块用 `mihomo -t` 校验临时文件，再原子替换配置。App 退出后，模块继续独立运行。
- 内置模块使用 SHA-256 校验后，通过 `ksud module install` 或 `magisk --install-module` 安装。保留 `/data/adb/minclash` 中已有的配置和日志，安装完成后提示用户重启，不自动重启设备。App 识别已安装版本和待重启的模块更新。
- App 和模块独立更新。界面、应用分流、图标或权限等 App 功能更新不会要求重装模块。仅模块功能修订号增加或现有模块缺少必要能力时提示更新；已发布的模块 0.0.1 与 0.0.2 功能一致，都可继续使用。模块安装确认、版本展示与导出文件名均读取内置模块自己的信息。
- `service.sh` 在 Android 完成启动后启动守护进程。守护进程监测 `minclash0`、策略路由和内核进程，故障后按 3 秒至 60 秒的间隔退避重试。停止时先发 `SIGTERM`，再检查并清理本次启动占用的规则。模块保留 `20882` 路由表及 `8799–8810` 优先级段，启动前会检查冲突。
- 网络恢复覆盖整个运行过程。Wi-Fi、移动网络、双卡上游或默认路由发生变化时，连续两次稳定采样后重建 TUN，并设置 30 秒冷却，避免网络抖动引起反复重连。无系统上游时显示「等待系统网络」；App 和通知同时通过 Android 网络回调及时刷新状态，模块独立运行。
- 热点共享代理默认关闭，此时热点客户端沿用 Android 原生网络共享。开启后，模块根据 Android 的转发规则和 `local_network` 表识别活动热点接口，为 IPv4/IPv6 添加到 TUN 的策略路由、局域网与回包路由、双向转发放行，以及 TCP/UDP 53 端口的 DNS 接管。接口变化时重建规则；停止 TUN、关闭共享或发生部分安装失败时，清理本模块记录的规则，不清空系统防火墙或共享路由表。额外保留策略优先级 `8796–8798`，检测冲突后拒绝安装共享规则。
- Android 热点 DNS 服务 `dns_tether`（UID 1052）通过优先级 `8795` 绕过本机 TUN，向直连的热点客户端返回真实 IP，避免订阅启用 Fake-IP 后将 `198.18.x.x` 发往运营商网络。该例外只匹配系统热点 DNS 服务，本机应用 DNS 继续由 TUN 处理。开启共享时，客户端 DNS 在 PREROUTING 即送往 TUN，仍使用当前配置的 DNS 与规则。
- 为防止网络共享加速绕过代理，共享开关开启期间会关闭系统硬件转发加速和可配置的 BPF 转发加速，原值保存在 Root 数据目录。关闭共享开关或卸载模块时恢复原值；期间用户或系统自行更改的值不会被覆盖。BPF 加速状态由系统服务在初始化时读取，部分系统首次开启共享需重启手机，App 会显示此状态。设备缺少 IPv6 NAT 时自动使用 IPv4 共享，并拒绝热点客户端的 IPv6 转发，供客户端回退 IPv4；界面会显示兼容模式。后台设置命令通过管道交给系统服务，避免将 Root 日志描述符传入 Binder；设置暂不可用时重试，不终止本机 TUN。
- 开启共享前检测系统命令、IPv4 NAT 与双栈防火墙；运行时确认 IPv4 上游可用性。每 15 秒复查加速设置、每 30 秒复查系统 BPF 实际状态和基础能力，发现设置漂移后重新应用。若实际 BPF 状态仍开启，会撤销共享规则并提示重启；无法确认加速状态时不会显示共享成功。本机 TUN 保持独立运行。
- App、通知和快捷磁贴共用会话状态判断。新版模块报告内核存活、IPv4/IPv6 路由及控制套接字就绪情况；状态文件与实际能力不一致时显示「连接待恢复」。旧模块继续按原状态协议工作。
- 通知控制开启后，App 将这一选择同步给支持恢复的新模块。模块检查通知心跳，服务中断或模块在后台重连后，最多每分钟尝试恢复一次当前用户的通知服务。不会修改系统通知权限，也不会越过用户在系统设置中的强行停止；取消通知开关后停止恢复。
- 导入保留 YAML 的节点、策略组和规则。只有节点或节点提供者的 YAML 会补上默认选择组和匹配规则。模块统一使用 Mihomo `mips` TUN、自动路由和 53 端口 DNS 接管。导入配置中的额外监听、外部控制器和 NTP 设置会被移除。未填写 DNS 上游时使用 Mihomo 内置默认值。支持手机本机流量，以及开启共享后的热点流量。请在测试时先关闭其他 VPN 或透明代理模块，Android 的私人 DNS 也可能绕过 53 端口接管。
- App 通过 Root 访问数据目录里的 Unix 套接字控制 Mihomo。手动切换的模式会在下次启动 TUN 时恢复。节点选择由 Mihomo 的 `profile.store-selected` 设置控制是否记忆。
- 应用分流按 Android 包名匹配，排在订阅规则之前。App 在私有数据中分别保存订阅源配置与个人应用设置，每次导入或更新时重新合并；恢复「跟随订阅规则」会移除对应的个人规则。更换订阅时若指定的代理组不存在，会拒绝更新并保留原配置，需先重新选择出口。保存失败时尝试恢复原配置和连接。应用列表需要查询已安装应用的权限，不上传应用清单。
- 应用列表优先申请设备支持的 `GET_INSTALLED_APPS` 动态权限，再通过普通接口查询。`QUERY_ALL_PACKAGES` 是安装时自动授予的普通权限，不能弹窗申请。若系统没有动态申请入口或授权后仍返回空列表，会提供应用设置和「用 Root 读取」选项；Root 仅在选择后启用，并在界面标明来源。记住选择后仍优先尝试普通查询，不调整系统权限。读取失败会明确提示，而非显示为搜索无结果。
- 配置和最近日志位于仅 Root 可访问的 `/data/adb/minclash`。重新安装模块时继续使用此目录中的配置。需要恢复网络时，可在 App 停止 TUN，或者在 Magisk 禁用模块并重启。

## 构建

准备 Python 3.11 或以上、JDK 17 或以上、Go 1.26.11、Android SDK Platform 36、Build Tools 36.0.0 和 NDK 27.0.12077973。通过 `ANDROID_HOME` 指定 SDK 目录，再运行 `python build.py`。Go 不在 PATH 时设置 `MINCLASH_GO`，NDK 安装在其他位置时设置 `ANDROID_NDK_HOME`。脚本校验固定 Mihomo 源码、官方 vendor 依赖和其他下载文件的 SHA-256，应用 `mihomo-patches/` 后测试并构建内核。模块 ZIP 及校验值嵌入 `dist/MinClash.apk`，模块和完整修改源码包也输出到 `dist`；提供安装包时一并提供源码包。详细构建参数见 [内核修改说明](mihomo-patches/README.md)。发布签名构建使用 `python build.py --release`，脚本会校验签名指纹并输出 APK 的 SHA-256。请私下备份现有的 `build/debug.keystore`，也可用 `MINCLASH_KEYSTORE` 指向备份位置。

App 当前版本为 `0.2.2`，构建 `versionCode=40`。内置模块为 `0.0.9`、`versionCode=18`、功能修订号 `revision=8`。本次通知与设置界面更新无需重装模块或重启手机。已安装该模块的用户无需重复安装；旧模块用户如需使用保活功能，需安装内置模块并重启，暂不使用该功能可继续沿用旧模块。App 依据模块功能修订号及必要能力判断更新，不依据 App 版本要求重装。

模块 0.0.9 新增「设置 → 后台连接保活」，默认关闭，旧模块继续使用现有代理能力。用户可开启并选择保守（空闲 180 秒、重试间隔 30 秒）、均衡（120／20 秒）或激进（60／15 秒），连续 3 次无响应后由系统判定连接失效，帮助 Telegram 等应用重连。开启前检查所选参数；不支持就退回原行为，并在设置页提示。正常 TCP 数据会延后探测，正常空闲连接仍保留，订阅重载保留当前会话的策略。

保存开关或强度不会直接打断现有连接，下次启动 TUN 时生效。运行中若有待应用更改，设置页提供「重连 TUN 使设置生效」，确认后短暂断线并尝试恢复原节点选择。保活开关保存在本机 Root 数据目录，关闭时选定的强度记在 App 本机偏好中，均不进入备份。不新增轮询、唤醒锁或全局 TCP 设置，UDP／QUIC 保持原行为。探测可能增加流量及耗电，Android 深度休眠仍可能暂停 CPU／网络，检测时间不是唤醒时限，也不保证即时后台推送。

0.2.0 的保活设置增加使用示例：Telegram 长时间处于后台后，返回前台仍显示「连接中」、消息刷新延迟时，可尝试启用均衡档，帮助识别失效连接并触发应用重连。强度弹窗使用可滚动的独立卡片，先展示档位取向，再显示空闲阈值和重试间隔；正常连接无需启用，探测参数不代表消息刷新间隔。选择档位不会自动开启功能，取消时不保存。

自定义规则及连接控制沿用 Mihomo 已有的 [规则格式](https://wiki.metacubex.one/config/rules/) 和 [连接 API](https://wiki.metacubex.one/api/)。订阅响应头字段与 [MetaCubeXD 的订阅用量约定](https://github.com/MetaCubeX/metacubexd/blob/main/README.md) 一致。

上游版本、模块安装规范和 TUN 参数可查阅 [Mihomo v1.19.33](https://github.com/MetaCubeX/mihomo/releases/tag/v1.19.33)、[Magisk 开发文档](https://topjohnwu.github.io/Magisk/guides.html) 和 [Mihomo TUN 文档](https://wiki.metacubex.one/config/inbound/tun/)。

## 验证

保留了首次 PID 检测误报修复，以及每 4 秒静默刷新状态的逻辑，自动查询不会反复禁用按钮。PID 回归检查可使用 Root 管理器的 BusyBox 运行 `tests/pid-check.sh /path/to/control.sh`，覆盖有效 PID、PID 重用、旧开机标识及失效记录。

`tests/AndroidInventoryCheck.java` 通过 Android `app_process` 和专用临时目录验证应用清单缓存、规则及代理组更新、缓存失效、异步图标加载和失败后的重新读取，不修改正在使用的配置。

`tests/hotspot-forwarding-check.sh module/control.sh` 检查默认的本机流量接管及双栈清理。`tests/hotspot-sharing-check.sh module/control.sh` 使用模拟路由和防火墙验证热点识别、双栈共享、DNS、接口变化、重复刷新、丢失规则恢复、部分失败回滚与冲突保护，不修改宿主网络。真机还需验证退出最近任务后的通知、开机恢复，以及热点客户端的 DNS 和实际代理出口。

`tests/runtime-recovery-check.sh module/control.sh` 验证持续网络切换、双卡路由变化、离线恢复、防抖冷却、通知心跳与用户停止状态。兼容场景和验证边界见 [兼容性回归矩阵](tests/COMPATIBILITY.md)。

`tests/NotificationLifecycleCheck.java` 在 JVM 验证旧通知偏好兼容、独立进程写入后实时读取、未完成／失败写入、短暂重连与持续停止、系统重建后的等待时限。Android 上的进程与最近任务生命周期仍需真机验证。

通知恢复使用 Android 的 [sticky 前台服务](https://developer.android.com/reference/android/app/Service#START_STICKY)及[开机与覆盖安装广播的启动豁免](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start)。BPF 状态检查依据 AOSP [BpfCoordinator 初始化时缓存加速状态的实现](https://android.googlesource.com/platform/packages/modules/Connectivity/+/refs/heads/main/Tethering/src/com/android/networkstack/tethering/BpfCoordinator.java)。
